Detect. Diagnose. Mitigate concept drift.

An interactive look at an adaptive ML pipeline, evaluated on the ELEC2 electricity-market stream.

Why models degrade over time

A model is trained once on a historical snapshot. After deployment, data keeps changing: new patterns, new relationships, new conditions. This is concept drift, and it can quietly erode accuracy even when the code never changes.

Takeaway: this project builds a pipeline to catch degradation early and respond to it. It does not try to prevent drift itself.

Detectors on the real ELEC2 stream

51ADWIN drift signals across 27,188 instances
304EDDM signals, far more sensitive
  • KS-test measures distributional shift per feature. PSI measures its magnitude.
  • ADWIN is an adaptive-window streaming detector. EDDM is error-distance based and suited to gradual drift.
  • nswprice and vicdemand shifted significantly (p < 0.0001) at every severity, even “none”. Real temporal drift already exists between the reference and the stream.

Key findings

  • Real drift already exists in ELEC2 at “none” severity.
  • Recall degrades faster than precision.
  • Adaptive strategies recovered more F1 than static retraining in the high-drift test.

Limitations and future work

  • Controlled drift doesn’t cover every real pattern
  • One primary dataset; results depend on model and detector configuration
  • No production deployment implemented
  • Next: live ingestion, automated monitoring and retraining, MLflow, cloud, human approval
