Why models degrade over time

A model is trained once on a historical snapshot. After deployment, data keeps changing — new patterns, relationships and conditions. This is concept drift, and it can silently erode accuracy even when the code never changes.

Takeaway: this project builds a pipeline to catch degradation early and respond to it — not to prevent drift itself.

Key findings

  • Real drift already exists in ELEC2 at “none” severity.
  • Recall degrades faster than precision.
  • Adaptive strategies recovered more F1 than static retraining in the high-drift test.

Limitations & future work

  • Controlled drift doesn't cover every real pattern
  • One primary dataset; results depend on model/detector config
  • No production deployment implemented
  • Future: live ingestion, automated monitoring and retraining, MLflow, cloud, human approval
